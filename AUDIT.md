# Пользовательский аудит — 12 октября 2026

Проверены сценарии покупателя, продавца и сборки ПК в локальном браузере. Для операций использованы отдельные тестовые аккаунты и изолированная база.

| Что мешало пользователю | Что изменено |
| --- | --- |
| После поиска RTX 3070 переход к процессорам оставлял старый запрос и давал пустой каталог | Переход в категорию сбрасывает чужие условия поиска. Полный набор фильтров хранится в адресе страницы, работает перезагрузка и «Назад» |
| Непонятно, почему выдача пуста | Видны активные фильтры с отдельным удалением; в пустой выдаче есть кнопка сброса |
| Сайт предлагал сравнивать товары, но сравнения не было | Кнопки в каталоге и карточке, панель выбранных товаров и таблица до четырёх предложений одной категории. Есть режим различий |
| После публикации нельзя исправить цену, описание или фотографию | Редактор из карточки своего объявления и профиля. Фото сохраняется, пока автор не заменит или не удалит его |
| Файл выбирался без возможности увидеть результат | Предпросмотр фото, проверка типа и размера, кнопка удаления |
| У своего товара была кнопка покупки | Автор видит переход к редактированию. Серверный запрет заявки на свой товар сохранён |
| Заявка после отправки превращалась в запись без действий | Продавец принимает, отклоняет или завершает; покупатель видит ответы, открывает состав и отменяет незавершённую заявку |
| В общей заявке продавец мог получить позиции и сумму других продавцов | Представление и ответы разделены по продавцам. Цены сохраняются на момент отправки |
| Заявка на сборку могла попадать продавцам отдельных деталей | Такие заявки остаются у покупателя для будущей обработки оператором |
| Бюджет задавался только ползунком | Добавлено точное поле суммы, синхронизированное с ползунком |
| Основные разделы неудобно переключать на телефоне | Нижняя навигация: главная, каталог, сборщик, корзина, профиль |
| Повреждённое сохранённое значение корзины могло остановить загрузку | Проверка типа локальных данных и отбрасывание некорректных ID |

Новые данные сохраняются на сервере; сравнение и несохранённая корзина остаются в браузере. Миграция базы добавляет ответы продавцов и поддерживает прежние заявки. Общая отмена заявки доступна до завершения сделки хотя бы одним продавцом; после завершения отдельный возврат пока не реализован.

## Что стоит делать следующим этапом

1. Кабинет сборщика: очередь заявок, согласование сметы и сроков, назначение исполнителя. Сейчас есть сохранение заявки и отмена покупателем.
2. Подтверждение email, восстановление пароля и уведомления об ответах. Сейчас обновление статуса видно при открытии/обновлении профиля, без push или автоматического опроса.
3. Модерация, жалобы и история репутации для реальных объявлений.
4. Лицензированные данные тестов комплектующих и статистика сделок для содержательной оценки цены/мощности. Сейчас оценка демонстрационная, это явно указано в интерфейсе.
5. Серверная пагинация и отдельное хранение фото при росте каталога.

Это отдельные продуктовые задачи с интеграциями и правилами обработки данных. Они не имитируются текущим интерфейсом. Проверки и границы результата описаны в [VERIFICATION.md](VERIFICATION.md).

## Повторный проход по пользовательским сценариям

Второй аудит подтвердил в Chrome: покупка после регистрации не продолжалась, незаконченный текст объявления терялся при переходе, все 36 начальных товаров выводились одним списком.

| Проблема | Исправление |
| --- | --- |
| После входа приходилось заново нажимать покупку | Форма заявки открывается автоматически после успешного входа или регистрации. Закрытие окна входа отменяет это намерение |
| Перед отправкой заявки не было списка товаров с ценами | В форме появился состав, цены каждой позиции и итог |
| Продавец мог изменить цену во время оформления | Перед открытием формы обновляется каталог; при отправке сервер сравнивает текущие цены с показанными покупателю. При изменении заявка не создаётся: покупатель обновляет сумму и подтверждает её заново |
| Обновление цены могло потребовать повторного заполнения контактов | Телефон, имя, город и комментарий остаются в форме после обновления состава |
| Снятый с продажи товар оставался в ранее открытой карточке | Доступность проверяется перед показом формы; вместо оформления появляется понятное сообщение |
| Незавершённое объявление терялось | Текст автоматически сохраняется в локальный черновик отдельно для каждого аккаунта и объявления. Новое объявление восстанавливается автоматически; для правки опубликованного товара есть явная кнопка восстановления |
| Случайный сброс мог удалить черновик | Сброс требует подтверждения. Успешная публикация или сохранение очищает соответствующий черновик |
| Длинная выдача без страниц | По 12 товаров на страницу, номер сохраняется в URL. Изменение фильтра или сортировки возвращает к первой странице |
| Снятое объявление называлось проданным | Статус в профиле теперь называется «Снято с продажи» |

Ограничения: черновики хранятся только в этом браузере, фото в них не входит; это явно написано рядом с формой. Пагинация пока клиентская, весь каталог по-прежнему загружается с сервера. Проверка ожидаемых цен используется интерфейсом сайта; запросы API без `expectedPrices` сохраняют прежнее поведение с расчётом актуального итога на сервере.

## Отдельный аудит поиска, сортировки и фильтров

До изменений в браузере не находились `RTX4060`, `4060 MSI`, `райзен 5600`, `кеч 4060` и `DDR4 32GB`. При новом запросе терялись категория, состояние и бюджет; мобильная панель закрывалась после каждого выбора.

Исправления:

- Поиск по словам в любом порядке, моделям без пробелов, характеристикам и названиям категорий. Добавлены распространённые русские варианты названий брендов и единиц памяти.
- Неверная раскладка исправляется только при отсутствии совпадений исходного запроса; исправление явно показано. При опечатке в слове предлагается запрос с реальными совпадениями. Цифры моделей не исправляются приблизительно.
- Новый запрос внутри каталога уточняет текущую выдачу. Кнопка «Во всём каталоге» явно снимает ограничения. Есть отдельная очистка запроса.
- По умолчанию запрос сортируется по релевантности, без запроса реальные объявления идут перед демонстрационными. Дешевле/дороже сортируется численно, при одинаковых значениях порядок устойчивый. «Сначала новые объявления» означает дату добавления через порядок ID, состояние товара выбирается отдельно.
- Фильтры по параметрам выбранной категории: видеопамять, сокет, DDR, объём накопителя, мощность, форм-фактор, частота монитора и другие имеющиеся в справочнике поля. Несколько значений одного параметра объединяются через «или», разных параметров — через «и».
- Счётчики учитывают другие активные ограничения. Варианты с нулевым количеством недоступны, уже выбранные можно снять. Список городов строится по объявлениям и включает выбранный город из URL.
- Пустая выдача предлагает снять конкретное ограничение с указанием количества результатов. Есть отдельный переключатель реальных и демонстрационных объявлений.
- Цена принимает пробелы при вставке (`150 000`); ошибки показываются около полей, не меняя выдачу. Ещё не применённая цена сохраняется при изменении другого фильтра.
- Мобильная панель остаётся открытой, кнопка результатов закреплена над нижней навигацией. Восстанавливаются фокус и прокрутка; панель сравнения не перекрывает открытые фильтры.

Границы: поиск и подсчёт фильтров выполняются в браузере по загруженному каталогу. Словарь русских вариантов ограничен, это не семантическая языковая модель. Товар без заполненной характеристики не попадает в соответствующий фильтр. Отсутствие совпадений не заменяется товарами с похожим номером модели.

## Проверка переходов и поиска реальных объявлений

Следующий проход выявил ещё два пропуска поиска: выбранная продавцом модель не учитывалась, если её не было в заголовке, а запросы `750 вт`, `144 гц`, `3200 мгц` давали пустой результат. Обычный браузерный возврат сохранял прокрутку, но ссылка «Каталог» в карточке не возвращала к исходным условиям.

Добавлено и исправлено:

- Поиск учитывает привязанную модель из справочника; в реальном объявлении отображается её название. Это модель, заявленная продавцом, а не подтверждение фактического состояния товара.
- Значения мощности, частоты, размеров и ёмкости индексируются с единицами измерения. Число и единица проверяются вместе: `8 Вт` не совпадает с памятью `8 ГБ`.
- В фильтрах появилась «Категория результатов». Она сохраняет запрос, цену, город, состояние и сортировку. Параметры предыдущей категории и отсутствующие в новой категории бренды снимаются с пояснением. Верхние карточки категорий по-прежнему открывают новый раздел каталога.
- В длинном списке брендов можно искать по названию. Уже выбранные бренды остаются видимыми; очистка поиска бренда не снимает фильтр товара.
- Кнопка «Вернуться к результатам» на странице товара восстанавливает адрес выдачи с фильтрами, сортировкой и номером страницы, прокрутку и фокус карточки. Контекст переживает обновление страницы товара и хранится только в текущей вкладке браузера.

Проверено на отдельных аккаунтах и тестовых данных; пользовательская база не использовалась для тестовых записей. Новые скриншоты: `brand-search-desktop.png`, `brand-search-mobile.png`, `return-to-results-desktop.png`.
