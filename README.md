# Component.kz

Локальный MVP маркетплейса ПК и комплектующих по предоставленным дизайн-референсам.

## Запуск

Нужен **Node.js 24 или новее**. Установка пакетов и сборка не требуются.

```powershell
cd "C:\Users\muxammedp\Startup Project"
npm start
```

Откройте **http://127.0.0.1:3000**. На Windows также можно дважды нажать `Start-Component.cmd`. Сервер работает, пока открыто его окно; `Ctrl+C` останавливает его.

Создайте свой аккаунт через «Войти → Зарегистрироваться». Предустановленных паролей нет.

## Возможности

- Главная, каталог, карточка объявления, профиль, избранное, корзина, размещение объявления, подбор и конфигуратор.
- Каталог с поиском, фильтрами по категории, состоянию, бренду, городу и цене, сортировка.
- Регистрация и вход; пароли хешируются через scrypt, сессии — серверные с HttpOnly / SameSite cookie.
- Пользовательские объявления с фотографией JPEG/PNG/WebP до 1,5 МБ. Снятие с продажи и повторная активация в профиле.
- Привязка объявления к точной модели из справочника: параметры берутся с сервера, товар участвует в подборе. Соответствие модели заявляет продавец, сервис его физически не проверяет.
- Серверное избранное и сохранённые сборки. Корзина и текущая несохранённая сборка сохраняются в браузере.
- Конфигуратор новых, б/у или смешанных комплектующих. Проверки сокета, памяти, БП, охлаждения и основных габаритов.
- Подбор полной совместимой сборки под бюджет и задачи.
- Оценка мощности и цены/мощности; сравнение суммы комплектующих с ценой продавца.
- Заявки на покупку и на сборку сохраняются в SQLite. Продавец реального товара видит контакты покупателя в профиле. Покупатель видит свои заявки.
- Адаптивный интерфейс для телефона и компьютера.

## Что означает AI-оценка

Без внешнего ключа работает **алгоритмический подбор и расчётная оценка**, а не языковая модель. Никаких выдуманных замеров FPS нет.

Для CPU/GPU заданы демонстрационные коэффициенты от 0 до 100. Индекс мощности: `round(min(GPU, CPU × 1.2) × 0.75 + CPU × 0.25)`. Цена/мощность: `clamp(индекс / цена × 42000, 1, 10)`, с округлением до десятых. Показатели задач также являются эвристиками. Это пример продуктовой механики, **не верифицированный бенчмарк и не текущая рыночная оценка**. Для коммерческого запуска коэффициенты нужно заменить лицензированными тестовыми данными и статистикой реальных сделок.

Опциональные текстовые AI-объяснения подключены через [OpenAI Responses API](https://developers.openai.com/api/docs/quickstart). Чтобы включить их, скопируйте `.env.example` в `.env`, заполните `OPENAI_API_KEY` и `OPENAI_MODEL` моделью, доступной в вашем API-проекте, затем перезапустите сервер. Ключ хранится только на сервере. Внешней модели передаются названия, характеристики, цены и расчёты выбранной сборки; контакты и профиль не передаются. Вызов выполняется только по кнопке объяснения для авторизованного пользователя, с ограничением частоты и тайм-аутом. Запросы могут тарифицироваться провайдером. При отсутствии ключа или ошибке сервиса UI явно показывает расчётный режим.

Живой внешний AI-вызов при разработке не проверялся: ключ и модель не предоставлены.

## Данные и устройство проекта

| Файл | Назначение |
| --- | --- |
| `server.mjs` | HTTP-сервер, API, авторизация, SQLite и AI-адаптер |
| `catalog.mjs` | Начальный справочник, правила совместимости, оценка и подбор |
| `public/app.js` | Страницы и клиентские сценарии |
| `public/styles.css` | Адаптивное оформление |
| `public/assets/` | Логотип и изображения из предоставленных референсов |
| `data/component.sqlite` | Пользователи, сессии, объявления, избранное, сборки и заявки |
| `tests/` | Автоматические тесты ядра и HTTP API |

SQLite создаётся автоматически при первом запуске. Начальные 36 объявлений помечены как демонстрационные. Пользовательские данные не стираются при перезапуске. Фото объявлений хранятся в SQLite. Содержимое `data` и `.env` не выдаётся HTTP-сервером и исключено из Git. Для резервной копии остановите сервер и скопируйте каталог `data`.

Картинки демонстрационных товаров — иллюстрации из пользовательских макетов, выведенные через CSS. Перед публичным запуском замените их отдельными фотографиями товаров с правом использования.

## Проверки

```powershell
npm test
```

Тесты запускают отдельный сервер с базой в памяти и не меняют пользовательские данные. Проверяются авторизация, изоляция аккаунтов, объявления, избранное, сборки, серверные суммы заявок, недоступность проданных товаров, некорректные фото, защита от межсайтовых запросов и ошибки совместимости.

Результаты разработки и браузерной проверки — в `VERIFICATION.md`. Скриншоты — в `screenshots/`.

Браузерный тест на Windows с установленным Google Chrome:

```powershell
npm run test:browser
```

Он сам запускает изолированный сервер с базой в памяти, проверяет пользовательские сценарии и ширины 360, 390, 768 и 1440 px, сохраняет скриншоты в `.qa/`, затем закрывает тестовые процессы. Если Chrome установлен в другом месте, укажите переменную `CHROME_PATH` с абсолютным путём к исполняемому файлу.

## Границы MVP

Это готовая локальная основа стартапа, а не запущенный коммерческий сервис. Публичная публикация не выполнялась. Реальная оплата, доставка, уведомления, модерация, подтверждение email, восстановление пароля и кабинет оператора-сборщика пока отсутствуют. Заявки на сборку сохраняются для дальнейшей обработки, но автоматически исполнителю не отправляются. Для демо-товаров заявки учебные.

Сервер по умолчанию слушает только `127.0.0.1`. Перед размещением в интернете нужны HTTPS, `COOKIE_SECURE=1`, корректный `PUBLIC_ORIGIN`, резервные копии, мониторинг, модерация и пользовательские правила. При масштабировании понадобятся отдельное хранение фото, пагинация, миграции схемы и более полная модель совместимости (BIOS, линии PCIe, разъёмы питания, QVL памяти и т. д.).
